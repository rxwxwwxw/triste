# H03 — guarded pure islands in an action-bearing grammar

`version(NPeggedPureIslands)` permits direct recognition and compatible compact
records for a proven pure, closed, nonrecursive public entry in an otherwise
action-bearing grammar. Ordinary builds retain their existing generated bytes.
This experiment does not change memo predicates, scalar reference bypass, seed
growth or invalidation; H04 remains separate.

## Semantic boundary

The H02 local effect graph and the existing acyclicity proof must both succeed.
Generated entry metadata grants permission only at `check`/`parseRecords` API
entry. A pure leaf called from an arbitrary composed or actionful parser stays
on the legacy path: callbacks can observe steps/depth or change input and limits.
Full trees, CTFE, recursive/unknown/actionful entries, tracing, finite budgets,
nonstandard allocators and failed arenas also retain the legacy path. The gate
checks context budgets and actual parse/output arena limits.

Compact records need a second proof. Legacy parent combinators can omit named
children with empty matches, and fuse/discard/drop/propagate can remove selected
descendants. A conservative shape analysis rejects those cases. Compiled
selection must omit anonymous nodes and agree at runtime with every compiled
rule kind. Uncompiled, anonymous-retaining and phase-dependent selectors fall
back. Named entries are required for records: `opCall` renames the legacy root.
These restrictions are necessary for exact node sequences, not performance knobs.

## Verification

The test-first commit is `7ef4e0d`. The fixture compares combinator and direct
backends inside each binary, then compares ordinary and opt-in transcripts.
It covers recognition, borrowed/owned records, full trees, success/failure
positions, exact trees/nodes, action and trace event order/state, input mutation,
callback-imposed limits, finite step/depth/parse/output budgets and mixed parser
composition. Positive counters separately demonstrate actual fast entry.
The budget matrix is outside the per-entry matrix to avoid duplicate cases.

Full oracle: DMD/LDC × selective/full/no memo × six projections = 36 pairs.
Additional uninstrumented DMD/LDC pairs exercise the compiled production gate.
Existing 72 code-generation goldens remain unchanged; both compilers pass the
17-module differential suite and flagged hotpath compilation without GC warnings.
All executable source modules exceed 90% line and branch coverage; see
`verification/`. Coverage includes the opt-in source units.

Memory checks use 4 GiB scopes and explicit outer timeouts plus the fixture's
45-second watchdog. ASan/LSan uses the established druntime-compatible
`detect_stack_use_after_return=0` setting described in H01. Memcheck disables
conservative GC scanning, as in H01/H02; no suppressions are added. Its
`--max-stackframe=8388608` accommodates the fixture's 5 MiB event-comparison
frame (the default otherwise misidentifies it as a stack switch). Both runners
produce identical transcripts. Memcheck reports zero errors, zero definite or
indirect leaks, and the same 32 possible / 216 reachable druntime bytes as H02.

## Measurement

Run `scripts/pure-islands-benchmark.py performance/results/H03/matrix`, then
`python3 performance/results/H03/report.py`. The driver builds all binaries before
measurement and pins source hashes. Timing binaries omit counters; diagnostic
binaries collect work separately. Each timing median uses three runs of seven
samples, with warmup, batched calls and destruction inside the clock. Controls
include finite limits, full trees, actual actions and repository JSON/CSV/PEG.
Two memo policies and three compiled projections cover 126 cases per cohort.
Raw CSV and metadata preserve compiler commands, source/binary hashes, time and
memory bounds, CPU, compile time and output signatures. The aggregate report
contains 31,752 timing samples and 1,512 counter samples.

## Decision

Retain the explicit experiment; do not promote it to a default. All 24 cohorts
pass output-signature checks, including action counts and guarded-off allocation
footprints. At 128 words, valid recognition takes 0.0024–0.0028 times reference
time across the six memo/projection cohorts. Compatible owned records take
0.0031–0.0033 (root projection) or 0.087–0.091 (leaf projection); the all-named
projection correctly falls back at approximately parity. The three individual
run ratios show the same large-entry benefit. See `timing-summary.md`,
`timing-ratios.svg` and the complete `ratios.csv`.

The largest regression is 1.792× for invalid 16-byte Identifier recognition with
a finite budget, full memo and leaf projection. The valid sibling is 1.752×.
These guarded-off cases retain exact output and allocation charges, but the
opt-in build is not overhead-free. The benchmark does not establish a universal
speedup, a default-promotion gate, or the roadmap's global ≤5× acceptance target.
The optimization targets pure entries inside this deliberately mixed grammar;
normal controls are reported separately in the complete matrix. JSON/CSV/PEG
controls span 0.953–1.042× (median 1.004×), actual-action controls
0.972–1.107× (median 1.008×), and full-tree controls 0.935–1.050×
(median 0.995×). These are measurements on this host, not universal bounds.
