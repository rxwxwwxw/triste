# R04 — isolate record copying

Hypothesis: record snapshots and replay can scale faster than final logical
output, even when recognition work is linear. Compare the R01 direct/indirect
chains with full/selective memo, both backends, and root-only/all-rule selectors.

No parser policy changes. Add diagnostic-only successful snapshot-copy counters
in RecordBuffer alongside existing restore and reallocation counters. Capture
logical node bytes, requested payload bytes, and peak arena retention separately.
Arena allocation is monotonic during parsing, so end-of-parse used bytes are the
peak retained bytes. Count both parse and output arenas, and report them separately.

Run bounded cohorts under a 4 GiB address-space limit and 60 second deadline.
Archive raw rows, source/compiler hashes and standalone plots. The root-only
projection is a control for output selection rather than a claim about all output.
Rollback instrumentation if default-build behavior changes; no optimization is
part of this milestone.

Command: `python3 scripts/record-copying.py performance/results/R04`.
The reference is the current broad-invalidation parser with its existing flat
snapshot API; compare work against R01 recognition-only cohorts.
