# H03 — opt-in pure entries inside action-bearing grammars

Use H02 structural/effect facts plus a closed acyclic-call proof to permit direct
recognition/record execution for pure API entry points in an otherwise actionful
grammar. Keep full-tree execution, action/opaque/recursive entries and unproven
composed callers on the existing path. Do not change cache predicates, scalar
reference bypass, seed handling or memo invalidation (H04 is separate).

Proof boundary: a producer entry-name list enables a private runtime gate only
when the entire API entry closure is proven pure. Merely entering a pure leaf
from an arbitrary effectful caller must not enable it: callbacks can observe or
change input, steps and limits. Require runtime execution, no trace, maximum
step/depth/context/actual arena budgets and standard allocators. Compiled record
selection and maximum output budget are also required for record mode. All other
contexts retain the reference fallback, including exact finite resource charges.

Build flag NPeggedPureIslands is explicit; ordinary builds/source goldens stay
unchanged. Tests first compare against combinators within each binary and against
an ordinary build: status, failure offsets, compact nodes, full trees, callbacks
(including parse-control state), tracing, borrowed/owned inputs, finite budgets,
projection variants and memo policies. Positive diagnostics prove real entry
activation. Measure uninstrumented 3×7 timing samples separately from counters,
including actual actionful and normal controls; no default promotion without
semantic equality and repeatable intended gains. Require compiler, formatting,
coverage, -vgc, sanitizer/Memcheck and staged-hook checks before implementation
commit. Preserve reference behavior if the experiment fails its stop rules.

Test-first `7ef4e0d`; implementation follows in git log. Retained behind explicit
