# X01 — Bounded Literal-Prefix Discrimination After FIRST-Byte Overlap

## 1. Hypothesis & Task Objective

In PEG grammars, alternatives in an ordered choice often have overlapping FIRST byte sets.
A simple FIRST-set check flags these as non-deterministic or ineligible for single-byte predictive dispatch (`predictiveChoice`).
However, many overlapping alternatives can be resolved by inspecting a bounded literal prefix:
1. Disjoint tails after a common prefix (e.g. `"ab" / "ac"` sharing prefix `"a"` and diverging on disjoint bytes `'b'` vs `'c'`).
2. Shadowed alternatives in ordered choice (e.g. `"a" / "ab"` where earlier alternative `"a"` unconditionally matches any prefix of `"ab"`, rendering alternative 1 unreachable).
3. Guarded alternatives (e.g. `"a" eoi / "ab"` or `&"ax" "a" / "ab"`, where the earlier prefix alternative is constrained by end-of-input or lookahead, preventing unconditional shadowing).

Milestone X01 provides bounded literal-prefix discrimination analysis in `npegged.analysis` following H01, preserving PEG ordered choice semantics and diagnostic details, without altering runtime parser execution semantics or generated parser bytes.

## 2. Precise Semantic Contract

1. **`DiscriminationKind` Enum:**
   - `disjointFirst`: FIRST byte sets are disjoint, single-byte predictive dispatch suffices.
   - `disjointTails`: FIRST bytes overlap, but alternatives share a bounded literal prefix and have disjoint discriminating bytes at a bounded depth.
   - `shadowed`: An earlier alternative is an unguarded proper prefix of (or identical to) a later alternative under PEG ordered choice.
   - `guarded`: An earlier prefix alternative is constrained by EOF (`eoi`/`endOfInput`) or a lookahead predicate (`&`/`!`), permitting later alternatives to be reached.
   - `unbounded`: Overlap cannot be resolved by bounded literal prefix analysis (e.g. non-literal, cyclic, or opaque rules).

2. **`BranchDiscrimination` & `ChoiceDiscrimination` Structs:**
   - Record ordered branch pairs $(i, j)$ where $i < j$.
   - Record `commonPrefixLength`, `commonPrefix`, `discriminatingDepth`, and detailed diagnostic explanation.
   - Retain `@nogc nothrow` compatibility for inspection where feasible.

3. **Analysis Methods:**
   - `ChoiceDiscrimination analyzePrefixDiscrimination(size_t exprIndex) nothrow` in `GrammarAnalysis`.
   - `ChoiceDiscrimination[] analyzeAllPrefixDiscriminations() nothrow` in `GrammarAnalysis`.
   - `renderDiscrimination(scope const(ChoiceDiscrimination)[] discriminations, bool json = false) nothrow` for deterministic text/JSON rendering.

4. **Zero Semantic Regressions:**
   - Does not alter code emission or runtime parser semantics.
   - Passes all 72 H01 source hashes, multi-compiler tests, and project constraints.
