# H01 — opt-in eligibility report

Add a cold `eligibilityReport!(memo, Selector, backend)` API with explicit status,
typed rule rows and deterministic text/JSON rendering. Report current emission
choices, not hypothetical optimizations: scalar-reference eligibility and direct
recognition/record entry are different decisions. Capture the actual emitter's
booleans without changing them or generated parser bytes.

Include grammar/backend/memo policy, original root expression, left recursion,
actual memoization, grammar-wide unknown/action evidence, scalar blockers, direct
fallback, and configured/selected/leaf/subtree record conditions. H02 will refine
reported effects to rule-local facts; H01 must not change purity or memo policy.
Tracing, CTFE and full-tree fallbacks remain visible in report documentation.

Tests first: mixed action + opaque + recursive + pure grammar, pure/recursive/
parameterized/Unicode/empty fixtures, both backends, all three memo policies,
with/without compiled selectors. Pin pre-implementation generated-source hashes
for all 72 combinations. Reports must be deterministic, valid JSON, and agree
with emitted entry points. Add adjacent source unit tests, bounded integration,
DMD/LDC, coverage >90%, formatting and memory checks. No performance claim:
reporting is cold and explicitly requested; generated parser bytes must not change.
