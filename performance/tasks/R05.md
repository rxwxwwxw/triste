# R05 — immutable output fragments in isolation

Hypothesis: explicitly composing immutable output fragments avoids repeatedly
copying an unchanged subtree during deep synthetic growth. This is a separate
experimental API in records.d; parser memo snapshots remain unchanged until R06.

A snapshot is an immutable binary composition of frozen canonical record leaves.
Copying an arbitrary existing RecordSnapshot is the conservative fallback. Leaves
normalize parent offsets; composition attaches only external roots of its right
operand to an explicit earlier node (or the enclosing replay parent). No stable
prefix, mutable-buffer identity, hash equality or append-only seed assumption.
Checkpoint/rollback chooses a previous immutable snapshot handle; replacing output
constructs a new composition. Old snapshots remain valid for their arena lifetime.

Replay uses an explicit arena-backed stack, checked sizes, sticky errors and a
transactional output checkpoint. It must match the existing RecordBuffer restore
for all fields, nested parent rebasing and finite allocation limits. Empty handles,
invalid attachment, invalid imported parents, integer overflow and allocation
failure require colocated @nogc nothrow tests. Tests retain old versions while
replacing roots and unrelated subtrees. Include a bounded integration oracle and
synthetic deep-growth measurements separating frozen bytes from replay bytes.

Acceptance: byte-identical initialized CompactNodes to the baseline, no repeated
freezing of unchanged subtrees, DMD/LDC and memory/coverage gates. No parser wiring
or optimization promotion in R05. Fall back to freezing a full flat snapshot when
there is no explicit immutable composition proof.

Baseline/candidate command: `bash scripts/shared-records-check.sh`. The test-first
commit must fail to compile until the experimental API exists. The runnable
reference uses existing RecordBuffer.snapshot/restore on exactly the candidate's
logical output; counters compare successful full-snapshot copy bytes.

If equality, finite-budget behavior or copy-volume acceptance fails, remove the
experimental implementation and retain the oracle/report explaining the failure.
Do not change the existing snapshot API or wire the experiment into peg.d.
