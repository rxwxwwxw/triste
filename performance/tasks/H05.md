# H05 — empty discarded-scanner entry

F05 selected the empty Sp whitespace/comment path. The initial source-level hypothesis was that discard's .scan arm bypassed the
existing emitEmpty child guard. Optimized code disproves it for Sp: the closed
sequence child guard is emitted and executes before the scanner calls. Confirm
optimized control flow and isolate entry cost before changing source.

Test first: exact recognition, borrowed/owned records, full trees, failure offsets,
traces, all leading bytes and short suffixes, comments, EOF and finite budgets.
Require >=15–20% repeated isolated gains, whole PEG controls, compiler/coverage/
memory/-vgc and staged-hook checks; abandon if the existing path already removes
the measured work or if correctness/performance gates fail. No other hotspot or
new scanner semantics belongs to this milestone.

## Outcome: abandoned as already optimized

Fresh optimized micro and full BenchPEG Sp control flow already batches the empty
path before any scan calls. Do not add the proposed duplicate discard guard.
The baseline micro has 126 timing samples; the whole PEG has three fresh probe
runs. 39,681-line exact transcripts match DMD/LDC/ASan/LSan/Memcheck; no source
change, source coverage hashes match H03. See performance/results/H05/README.md.
This does not meet a new 15–20% improvement gate and is not a claimed optimization.
H06 is the next independent milestone; another H05 hotspot needs a separate task.
