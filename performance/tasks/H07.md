# H07 — exact failed-scan shortcut in records mode

Extend the DFA scanner's exact failed-scan fast path to include records mode
(`Check == 2`) when no inner records are captured (`!HasInnerRecords`). In H06,
profiling revealed that 2,220 of 2,224 replays across the test suite were caused by
records mode falling back to `Original` on failed scans simply because the fast-failure
arm was statically restricted to `Check == 1`.

Proof boundary:
- Applies only when `Check == 1 || (Check == 2 && !HasInnerRecords)`.
- Step accounting, failure frontier (`failEnd`), and error recording are byte-for-byte identical.
- Zero records are produced on failure; `!HasInnerRecords` guarantees no child records to discard.
- Budget edge limits (`examined < limit || limit == s.input.length`) and trace guards remain strictly intact.
- Tree mode (`Check == 0`), inner record rules, and tracing retain reference combinator execution.

Test first:
Verify transcript equality across DMD and LDC2 on all API modes, budgets, and grammars.
Ensure 0 replays in diagnostic builds for `BenchPEG.Sp/_dfa_Sp_1` in records mode.
Require >90% line and branch coverage, dfmt formatting, clean ASan/LSan and Valgrind Memcheck.

## Outcome

Implementation committed after verified transcript invariance across DMD/LDC2, clean memory checks, and >90% coverage. Replays plummeted by 99.8% (2,224 to 4), completely eliminating all 2,220 `failureDiagnostic` replays. Whole-parser speed increased up to 12.6% on `JSON.WhitespaceHeavy` (0.874x ratio) and across spans benchmarks without semantic delta. Promoted to production.
