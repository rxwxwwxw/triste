# H06 — scanner eligibility, bypass and replay diagnostics

Use explicit NPeggedScannerMetrics builds only. Caller-owned fixed-capacity rows
aggregate allocation-free per-region/per-rule events and report truncation without
losing totals. Attribute static eligibility, attempts, scan acceptance/rejection,
fast success/failure, Original calls, replays, examined frontier span and replayed
overlap span. Reasons distinguish tree capture, selected inner records, invalid
DFA, state/position/step/trace/depth guard, speculation budget edge, failure replay,
primitive scan alias and direct record lowering. A byte span is a frontier range,
not a physical byte-load count or a claim about every branch Original executes.

Generated diagnostic labels associate runtime events with rule and region. Static
rule metadata exposes emitted-region counts and root regularity proof, including
rules with no proven region. Ordinary generated bytes and scanner semantics must
remain unchanged. No failed-scan shortcut belongs to this task (H07 is separate).

Test first: compare full result/trace/allocation transcripts with diagnostics off
and on, both compilers, all API modes, guards and budgets. Colocated source units
must cover reason precedence, terminal outcomes, alias/direct-lowering bypass,
null/truncated sinks and aggregate/row conservation. Profile the actual PEG cases
plus JSON/CSV controls with counters, never interpret diagnostic times as speed.
Require >90% source coverage, dfmt, GC diagnostics, ASan/LSan, Memcheck and staged
hook validation before committing implementation.
